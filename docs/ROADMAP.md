# Iskra Learn — план развития

## Что уже есть в MVP
- Одностраничный адаптивный интерфейс на HTML/CSS/ES modules.
- Три учебных направления и редактируемый каталог тем.
- Три обратимых формата объяснения: пример/история, шаги, схема.
- Мини-задания, подсказки, счётчик результатов текущей сессии.
- Конфигурация отдельно от контента и алгоритма адаптации.
- Никакой записи аудио, регистрации, серверного хранения или психологической классификации.

## Архитектурные границы
- `src/config.js`: настройки, доступные параметры и feature flags.
- `src/content.js`: каталог учебного контента и задания.
- `src/adaptation.js`: прозрачная политика выбора подачи; заменяйте её после проверки гипотез.
- `src/app.js`: интерфейс и состояние текущего урока.
- `src/styles.css`: оформление.

## Следующие этапы
1. **Контентная модель:** версионируемый JSON-формат тем, учебных целей, уровней сложности, правильных ответов и объяснений.
2. **Педагогическая модель:** фиксировать освоение конкретных навыков по истории ответов, не выводить «тип личности» из голоса.
3. **Тестирование:** unit-тесты адаптации, доступность клавиатуры/скринридеров, тестирование на мобильных устройствах.
4. **Учительский режим:** редактор уроков, просмотр прогресса с согласия семьи и школы, возможность исправить неверные данные.
5. **Аккаунты и сервер:** добавлять только при необходимости; проектировать роли и права доступа, шифрование, сроки удаления, аудит и резервное копирование.
6. **ИИ-провайдер:** подключать только через серверный API. Не хранить секретный ключ в браузере или репозитории. Начать с генерации объяснений из проверенного контента и строгого формата ответа.
7. **Аудио (необязательно):** отдельное информированное согласие родителя/опекуна и понятное согласие ребёнка, минимизация хранения, кнопка удаления. Использовать речь только для добровольно заявленных интересов/вопросов, не для диагностики эмоций, интеллекта или личности.
8. **Валидация:** сравнить с базовой версией, измерять усвоение и отсроченное воспроизведение, а не только вовлечённость; проверять разницу результатов по возрасту, языку и доступности.

## Ограничения текущего прототипа
- Это демонстрация интерфейса, а не полноценная учебная платформа.
- Прогресс не сохраняется после перезагрузки.
- Возраст меняет формулировку, но не является оценкой развития.
- Логика адаптации намеренно простая и не прошла эмпирическую валидацию.
- Примерные задания иллюстрируют механику; учебный контент требует экспертной проверки.
- Внешний Google Fonts запрашивается браузером; для полностью офлайн-режима удалите импорт в CSS и используйте системные шрифты.

## Локальный запуск
Откройте `index.html` в браузере. Если ES modules заблокированы при открытии через `file://`, запустите любой локальный статический сервер, например `python -m http.server 8000`, и откройте `http://localhost:8000`.

## Definition of done для следующего этапа
- Каждый вывод профиля связан с наблюдаемым событием и имеет объяснимую причину.
- Пользователь может изменить или сбросить профиль.
- Данные детей не используются для скрытой диагностики.
- Контент проверен предметным экспертом.
- Есть тесты, политика приватности и проверенный процесс удаления данных до пилота с реальными детьми.
