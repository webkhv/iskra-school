# Accessibility and family usability checklist

This checklist is a manual release gate, not a claim that the prototype already conforms to a formal accessibility standard.

## Keyboard and focus

- [ ] Complete a lesson using only Tab, Shift+Tab, Enter and Space.
- [ ] Focus indicators remain visible on selects, style choices, answer options and action buttons.
- [ ] Focus order follows the visible reading and task order.
- [ ] Changing a topic or subject does not leave the learner in a confusing state.
- [ ] After checking an answer, the feedback is announced without requiring the learner to locate it visually.

## Screen reader and non-visual use

- [ ] Page language is announced as Russian.
- [ ] Every input has a meaningful associated label.
- [ ] Selected explanation format and selected answer are announced as pressed/selected.
- [ ] The question is programmatically associated with its answer options.
- [ ] Correct and incorrect feedback is available through the live region.
- [ ] The visual scheme has a meaningful text alternative; no answer depends only on colour or position.
- [ ] Parent summary labels make sense when read without the visual layout.

## Visual and cognitive accessibility

- [ ] Check contrast for body text, muted labels, controls, borders and feedback.
- [ ] Zoom to 200% and check that content and controls do not overlap or disappear.
- [ ] Test a narrow mobile viewport and both portrait and landscape orientations.
- [ ] Check reduced-motion preferences if animation is added.
- [ ] Instructions are concise and avoid time pressure, shame or fixed ability labels.
- [ ] Error recovery and reset behavior are obvious and reversible.

## Family usability

- [ ] Children can explain what the app does and what it does not do.
- [ ] Parents understand that the summary describes this session only and is not a diagnosis or stable ability score.
- [ ] Children can change explanation format without penalty.
- [ ] Guardian notices, consent and age-appropriate child assent are reviewed before any research session or data collection.
- [ ] Any usability findings are recorded without unnecessary identifying information.

## Before public launch

- [ ] Perform automated accessibility checks in a browser-based test environment.
- [ ] Test with keyboard and at least one screen reader on supported platforms.
- [ ] Have educators review all lesson content.
- [ ] Review applicable legal requirements for the actual launch markets.
- [ ] Document unresolved issues and block release for issues that prevent task completion or create material privacy/safety risk.
